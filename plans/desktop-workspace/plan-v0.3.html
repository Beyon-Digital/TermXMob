01 / Confirmed direction and changes

Scope approved. Design in progress; do not begin app implementation.

This v0.3 revision supersedes v0.2. The four open questions are answered. All ten Further Parity families remain mandatory. Only external-browser tab bridging is explicitly removed by the user.

Built-in browser only

Users browse and hand over tabs inside TermX. No Chrome, Edge or Safari extension, cookie import, or external live-tab attachment. External browsers still load the same TermX web UI and control the connected host’s built-in browser.

Smaller Auto Review Model

Routine permitted actions proceed without interrupting the user. Hard policies and scoped remembered rules run first; a separate small reviewer handles eligible uncertain actions; sensitive or unresolved actions pause.

Replaceable identity

Local password → managed session/JWT, generic OIDC, and a custom-adapter reference implementation. All use the same principal, session and authorization contracts.

Bring-your-own runners

Enroll or provision dedicated user-owned VM/container runners; stream logs/results; enforce grants, budgets, stop and teardown. No TermX-managed cloud fleet is included.

Same experience, honest capability differences. Both surfaces share tabs, layouts, grants and session identities. Native adapters add OS file pickers, secure storage, window controls, app capture and notifications. A normal website does not receive access to other local tabs. TermX offers only its host-managed built-in browser; native Computer capabilities remain separately permissioned.

Execution location is explicit. An external browser controls the connected host or selected runner. Its local filesystem, browser profile and localhost are not automatically those of the host. Uploading local files is a separate authorized action. Connecting the viewer’s existing browser tabs is out of scope.

Reuse, do not rewrite blindly. Retain Tauri/Python initially; replace the Expo web publishing step with the independent desktop build. Reuse viable CodeMirror/xterm logic, domain contracts and Relay behavior. Browser rendering and cloud execution have independent ports; neither may force an unrelated runtime or UI rewrite.

Shared data and delivery contract

Use host-owned canonical opaque IDs, Relay Node identity and cursor connections for paginated domain data. Retain dedicated streamed/PTY transports where required. Changes to the new UI must not break mobile APIs. Version the UI/host capability handshake and migrations; incompatible bundles must show an actionable update state instead of an Expo fallback.

Event consumers reconcile from durable cursors and stable event IDs. Rendering the same session in two windows must not duplicate a run, subscription effect or file mutation.

Control state machine

Human control → One task handoff → Agent control → Verify result → Human control
Agent control → Approval / private login / takeover → Explicit resume + re-observe

Tab permission is not account isolation. Two tabs in the same browser profile can share authentication. A grant constrains the automation broker, but a compromised profile/worker or broad shell access can exceed a UI-only tab boundary. Separate profiles/workers and OS-level isolation are required where users or tenants do not trust each other.

Browser integration ports and implementation proof

Proposed BrowserPort: create/attach/close tab, list authorized tabs, navigate, observe, act, claim/release control, capture, subscribe events and manage scoped profile lifecycle. Every command carries a principal, session, grant, tab ID and document/lease revision. Reject stale actions after navigation or takeover.

Baseline candidate: an isolated managed Chromium worker controlled through a narrow Playwright/CDP broker, with an authenticated interactive browser view in the shared web UI. Desktop-native embedding is an optimization behind a view adapter, not a second UX. A raw Playwright window or screenshot-only mock does not meet the in-app handoff requirement.

Before fixing the renderer, verify local latency, typing/IME, clipboard, popups, downloads, zoom, keyboard accessibility, platform packaging and remote viewing. A streamed surface is a candidate, not a proven production integration. Provide keyboard-accessible controls and meaningful page context; a canvas alone is not accessibility parity.

Never expose raw CDP to agents or external networks. Validate targets and network access, including redirects, private networks, cloud metadata and privileged local services. Allow development ports only through explicit project grants. In-app remote content receives no TermX credentials or Tauri command capabilities. Browser-control permissions cannot be bypassed by an unrestricted shell in a claimed restricted environment.

Playwright documents isolated contexts; Tauri documents per-window/webview capability boundaries. These are building blocks, not proof of full browser security. External-tab extension research is retained only as historical context and is not part of the delivery scope. [W18][W19][W20]

Current ChatGPT docs distinguish its built-in separate browser profile from Chrome-extension access to existing signed-in tabs and show browser annotations. TermX implements only the built-in profile path. Existing external-tab control is deliberately excluded. [W9][W16]

Enterprise authentication does not require each endpoint to know the provider. OIDC uses Authorization Code + PKCE with validated state, nonce and redirect targets. A custom adapter may integrate an existing identity implementation. For direct enterprise access tokens, only an administrator-configured verifier or exchange route is trusted; ID tokens are not generic API access tokens. [W21][W22]

JWT, storage, refresh and revocation contract

Proposed defaults: 5-minute access-token lifetime; rotating opaque refresh tokens; configurable idle/absolute device-session limits; single-flight refresh per session across windows. These are starting parameters, not yet measured policy. Detect refresh reuse and revoke the affected family, without creating false positives from legitimate coordinated refreshes.

Access claims include issuer, audience, subject, session ID, issued/expiry times, token type and policy context. Minimize embedded personal data. Authorization is evaluated against current server policy and resource membership; a stale role claim cannot preserve removed access. API audience identifies the intended host/gateway, with host-scoped permissions enforced at the target.

For the same-origin browser, keep long-lived secrets in secure HttpOnly cookies and use CSRF protection plus strict origin checks. Browser API access may use a same-origin session facade or protected access cookie; clients must not persist bearer tokens in localStorage. Native/CLI refresh credentials use OS secure storage, with short-lived access tokens in memory. No password/JWT in URL parameters, logs or analytics.

Check session revocation on privileged requests and publish invalidation to sockets/control leases; JWT expiration alone is not immediate logout. Revalidate socket authorization and permissions over long-lived sessions. On sign-out, clear authorized client state and browser-control grants; audit job policy separately from UI connection state.

JWT validation and OAuth session handling follow the cited standards. The durations, port names and endpoint shapes here are proposed TermX decisions. [W17][W12][W22]

Transport, adapter rollout and legacy migration

Proposed contract names: GET /auth/methods, local POST /auth/login, provider begin/callback, POST /auth/refresh, POST /auth/logout, session inventory/revoke and GET /auth/me. Final paths and GraphQL equivalents belong in the implementation handoff. Method discovery reveals only safe branding and available flows, never secrets or user existence.

Protect GraphQL/HTTP, subscriptions, raw PTYs, file downloads, preview proxies, browser control, remote screen/input and legacy routes. TLS is required for remote transport. Local initial setup is bound to a trusted host-admin path; a network visitor cannot claim an unconfigured machine.

Ship a compatibility facade over the existing Auth calls, map scopes without elevating legacy credentials, and provide a bounded migration/re-pair route. Stop accepting the owner password as a general API bearer after migration. Test native mobile compatibility during the transition; never retain a forgotten unauthenticated legacy path.

Adapter updates are validated, versioned, health-tested and activated atomically. Unknown issuers, adapter crashes and policy-store failure fail closed. Preserve an explicit audited local administrator recovery route; do not silently fall back from failed enterprise SSO to password access. Account/IdP loss revokes or expires sessions under the declared policy.

Authentication does not sandbox a shell. Named users and JWT roles cannot isolate two people executing as the same unrestricted OS user. Multi-user hosts and cloud runners require restricted OS identities or containers/VMs, separate credentials/files/browser profiles and enforceable resource boundaries. Where that is absent, disclose a trusted-shared-machine boundary rather than claiming tenant isolation.

Three authorities stay separate: signing in to TermX, authorizing an engine/provider account, and logging in to a website. None grants the other two. Lock, logout, Stop task and Stop host are separate actions with clear effects on existing jobs and capture/control.

Remembered action policy: offer Allow once, this session, or a bounded project/agent rule, with inspect/edit/revoke controls. Separate filesystem/network/browser grants from run-budget renewals. Auto Review is the default after an explicit task handoff within the active policy. Unattended schedules still require an explicit delegated grant. Neither can exceed host policy or authorize unrelated high-impact actions.

09B / Auto Review — low friction, bounded authority

Approve the workflow once. Review its actions automatically.

The smaller model is a bounded policy reviewer, not an executor and not a second agent loop. The host broker remains the enforcement point. The reviewer cannot grant itself tools, expand a sandbox, change roles, write remembered permissions or issue credentials.

Reviewer configuration and action contract

Default strategy: choose the smallest eligible model from an already configured, approved local or remote provider after a held-out tool-safety evaluation. Pin its provider/model/version and policy prompt. Prefer a qualified local option when available; do not force an unqualified small model merely to minimize cost. Final model selection is an implementation gate, not a product blocker or an invented available model ID.

Discover provider models/capabilities; require reliable structured verdicts, measured latency/cost, adversarial-case performance and enterprise data-residency compliance. Tool metadata is host-owned. Page text, screenshots, files, tool results and executor summaries are untrusted evidence—not policy or user consent. Pass only necessary redacted context. Do not send cookies, passwords, tokens, secret-store values or private-login frames to any reviewer provider. The reviewer has no executable tools and no durable permission-write access.

Performance targets, not measured results: safe rule checks should add negligible user-visible delay; reviewer p95 target ≤2 seconds on the selected reference setup, with a 5-second decision deadline. A timeout becomes NEEDS_USER for that action. Tune only after tests. Deduplicate concurrent reviews for the same action; never cache a blanket approval for every future click.

Any cache/permit is bound to the action, identity, project, profile, account, target, grant, policy/reviewer version and document/lease revisions. Revalidate immediately before execution. Navigation, policy changes, expiry or takeover invalidate it. A state-changing submission is never replayed just because a response was lost.

Engine coverage and isolation

Route native engine approval hooks and TermX/MCP/browser tool boundaries through the same broker. Preserve native session ownership and resume semantics. Where a harness cannot expose all actions for interception, enforce OS/network restrictions and disclose the exact coverage; do not claim total Auto Review protection. Direct shell/CDP/network access must not bypass the browser broker in an environment described as restricted.

Keep host, workspace and agent execution profiles distinct. The existing human host terminal is not magically sandboxed by a UI toggle. Restricted agent/workspace profiles need enforceable kernel/VM/container constraints. Shared browser profiles are not tenant isolation.

Unattended jobs use explicit scoped job grants with expiry/budget; they do not borrow a logged-in UI session indefinitely. Revocation closes leases and prevents future protected effects. Review states survive reconnect/restart without replaying completed operations.

The layered boundary design is consistent with OWASP least-privilege guidance and OpenAI’s tool-boundary review guidance. These sources do not prove the smaller model is reliable enough; TermX must evaluate it. [W23] [W24] [W25]
