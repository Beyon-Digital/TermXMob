The desktop release workflow builds `desktop/workspace` with its frozen pnpm lockfile and includes the same generated UI in the Python sidecar served to desktop and external browsers. Expo is the separate mobile client.

`desktop/scripts/prepare_runtime.py` stages Chromium matching Playwright 1.58.0, verifies Microsoft js-debug 1.140.0 against SHA-256 `27dab92937ec1ab35821ae955aac867544fe06a1b6307229049f2d789af10968`, and installs the exact JavaScript/TypeScript/HTML/CSS/JSON language packages from this directory's npm lockfile. The Python extras provide basedpyright, platform Node, debugpy, FFmpeg and document/table/deck dependencies. Package assets retain upstream licenses; the PyInstaller collector includes package metadata and data. Runtime sources/versions are recorded in the bundled manifest.

Build order in CI: dedicated workspace tests/build → install Python development/media/webrtc extras → browser system dependencies on Linux → stage runtime assets → PyInstaller sidecar → platform signing → Tauri delivery build. Rust delivery binaries are built only by GitHub CI. Signed installers and secure-store/window restore behavior need validation on each platform; preparing these scripts does not prove a release has run.

Python debug targets require a project-compatible Python interpreter on the host (`TERMX_PYTHON_INTERPRETER` can select it); the frozen sidecar is only the debug adapter. Rust language tooling remains the host's installed `rust-analyzer`. Linux DEB/RPM declares Chromium libraries; AppImage users must have equivalent platform libraries and a session keyring/Secret Service configured.
