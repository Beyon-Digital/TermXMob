# Dedicated AI runner

Build from the repository root with `docker build -f desktop/runner/Dockerfile -t termx-runner:workspace .`. Enroll that locally available image in the workspace runner manager; TermX resolves its immutable image ID and never downloads an image during enrollment. Select isolated networking, then explicitly select the runner, configured API account reference and model in the conversation composer.

The installed Python worker reuses `AgentManager` and its bounded coding tools, task budgets, streaming events and approvals. Provider requests travel through a bounded Docker stdio broker. API keys stay in the host credential store. The actual container must have network disabled, UID 65534, a read-only root, no host mounts, dropped capabilities, no privilege escalation, fixed CPU/memory/PID limits and only the three admitted temporary writable mounts. Preflight inspects the actual container and probes the installed protocol before any task dispatch.

File state is fingerprinted by the worker before requesting host review. The host binds approval to the exact arguments, state, principal, project, task, account, policy and runner lease. The worker checks that file state again immediately before the effect. Shell requests require exact human review because their effect is unknown. The configured smaller reviewer can allow eligible structured file edits. Review permits are consumed once before release, and completion is recorded separately; a missing completion has an unknown outcome. Container shell commands cannot reach providers or the host API through a network.

Conversations, canonical task records and ownership exist before dispatch. Remote task cancellation stops the dedicated container, steering reaches the running worker, and approval decisions reach the exact remote request. A host restart stops affected containers and reports unknown outcomes. Requests are never replayed on the local host or retried automatically after an ambiguous remote result. Upload source through the runner manager and explicitly export the resulting artifacts after verification.

The qualified engine port currently supports the internal engine's registered coding tools. Native CLI subscriptions, ACP, browser/computer tools, host hooks and automatic host credential or file copying are excluded from this isolated engine port. Their local counterparts remain available through the appropriate local session. An unsupported remote capability cannot be selected as a working integration.

Provider-free proof: `TERMX_TEST_RUNNER_AGENT=1 TERMX_RUNNER_IMAGE=termx-runner:workspace .venv/bin/python -m pytest -q tests/test_runner_agents.py::test_real_network_isolated_runner_agent_provider_review_controls`. This exercises the installed image, host fixture provider and reviewer, real remote writes, shell review, artifact export and cancellation without billing a provider. The default tests also exercise the actual Python worker subprocess and changed-file refusal in isolated temporary state.
